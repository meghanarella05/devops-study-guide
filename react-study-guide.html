⚡ Critical Concepts for 90%
🔵 Declarative vs Imperative
React is declarative — you describe WHAT you want; React figures out HOW. Imperative = step-by-step instructions. Declarative = outcome-driven.
🟢 Container vs Presentational Pattern
Container = logic, API calls, state. Presentational = pure UI from props. Separates concerns, improves reusability.
🟡 Higher-Order Components (HoC)
Function that takes a Component and returns an enhanced Component. Pattern: const Enhanced = withSomething(MyComponent)
🔴 Anti-Patterns to Avoid
1) Init state from props 2) Mutate state directly 3) Use array index as key 4) Spread props to DOM elements
🟣 Reconciliation
React's process of diffing the virtual DOM tree and updating only what changed in the real DOM. Uses element type + key to decide.
🏆 Top 10 Must-Know Facts
  • JSX is syntactic sugar — compiled to React.createElement() by Babel
  • Elements are immutable objects — type + props describe what to render
  • setState is asynchronous — don't rely on immediate state after calling it
  • Stateless functional components — no state, no lifecycle, no this
  • PropTypes — runtime type-checking, disabled in production
  • Keys in lists — must be stable, unique, not array index
  • componentDidMount — use for data fetching (not componentWillMount)
  • Controlled components — React controls form field value via state
  • Event delegation — React attaches one handler to root, not each DOM node
  • renderToString — server-side rendering, returns HTML string

Chapter 1: React Fundamentals

📖 Declarative vs Imperative
Imperative (HOW)
Step-by-step DOM manipulation. Tell browser exactly what to do each step.

Like: "Get a glass → fill with beer → hand it over"
Declarative (WHAT)
Describe the desired state. React figures out the steps.

Like: "Beer please."
// Imperative
const map = new google.maps.Map(...)
const marker = new google.maps.Marker(...)
marker.setMap(map)

// Declarative (React)
<Gmaps zoom={4} center={myLatLng}>
  <Marker position={myLatLng} />
</Gmaps>
🧱 React Elements vs Components
Element
Plain JS object describing what to render. Immutable. Has type and props. If type is a string → DOM node. If type is a function → Component.
Component
Created via createClass, extends React.Component, or stateless function. React manages instances at runtime. Multiple instances possible.
Reconciliation
React's diffing process. Recursively resolves component types until it has a pure DOM tree. Powers both React DOM and React Native.
⚠️ JavaScript Fatigue
  • React is just a small library — can use with just a script tag
  • create-react-app scaffolds everything with one command
  • Start minimal, add tools only as needed
  • Two packages: react (core) + react-dom (browser)

Chapter 2: Clean Up Your Code

📝 JSX Essentials
What is JSX?
XML-like syntax that compiles to React.createElement(). NOT HTML. Requires Babel to transpile.
// JSX
<button className="btn">Click</button>

// Compiled JS
React.createElement('button', {className: 'btn'}, 'Click')
JSX vs HTML Differences
• class → className, for → htmlFor
• Style = JS object with camelCase: style={{ backgroundColor: 'red' }}
• All elements must be wrapped in one root
• Boolean attribute: <button disabled /> = disabled: true
• Spaces between elements: use {' '}
• Capital letter = Component, lowercase = DOM element
🔀 JSX Patterns
Conditionals
<div>{isLoggedIn && <LogoutButton />}</div>
{isLoggedIn ? <LogoutButton /> : <LoginButton />}
Loops
<ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>
Spread attributes
const foo = { id: 'bar' }
return <div {...foo} />  // passes id="bar"
Multi-line (always wrap in parens!)
return (
  <div>
    <Child />
  </div>
)
🧹 ESLint
  • Error levels: 0=off, 1=warn, 2=error
  • Config in .eslintrc file
  • Plugins: eslint-plugin-react for React rules
  • Airbnb config: most popular React style guide
  • Enforce: indentation, prop sorting, no duplicate props, no unused vars
λ Functional Programming Basics
Pure Functions
No side effects. Same input → same output. Easy to test.
Immutability
Never mutate data. Create new copies instead. Use concat not push.
Currying
Convert multi-arg function into chain of single-arg functions.
Composition
Combine functions to create new ones. Foundation of HoCs.
UI as a Function
UI = f(state) — same state always produces same UI

Chapter 3: Create Truly Reusable Components

🏗️ Three Ways to Create Components
1. createClass (legacy)
const Button = React.createClass({
  getDefaultProps() { return { text: 'Click' } },
  getInitialState() { return { clicked: false } },
  render() { return <button>{this.props.text}</button> }
})
2. ES6 Class (standard)
class Button extends React.Component {
  constructor(props) {
    super(props)
    this.state = { clicked: false }
    this.handleClick = this.handleClick.bind(this) // bind in constructor!
  }
  render() { return <button>{this.props.text}</button> }
}
Button.propTypes = { text: React.PropTypes.string }
Button.defaultProps = { text: 'Click me!' }
3. Stateless Functional Component (preferred when possible)
const Button = ({ text }) => <button>{text}</button>
Button.propTypes = { text: React.PropTypes.string }
🔑 Autobinding Gotcha
Problem with arrow functions in render
// Creates new function on every render — bad for perf
onClick={() => this.handleClick()}
✅ Best: Bind in constructor
constructor(props) {
  super(props)
  this.handleClick = this.handleClick.bind(this) // ✅
}
🧪 State Rules
  • Minimal state: only what's needed, nothing derivable
  • Don't put in state: values that don't affect render
  • Don't put in state: values computable from props
  • setState is async: use callback setState({}, () => {})
  • Merge, not replace: setState merges with current state
  • Store API subscriptions/timers as this.request, not in state
❌ Bad: Derivable value in state
this.state = { price: `${props.currency}${props.value}` }
// Won't update when props change!
✅ Good: Compute in render
getPrice() { return `${this.props.currency}${this.props.value}` }
render() { return <div>{this.getPrice()}</div> }
📋 PropTypes
Button.propTypes = {
  text: React.PropTypes.string.isRequired,
  onClick: React.PropTypes.func,
  count: React.PropTypes.number,
  style: React.PropTypes.object,
  children: React.PropTypes.oneOfType([
    React.PropTypes.array,
    React.PropTypes.element,
  ]),
  user: React.PropTypes.shape({
    name: React.PropTypes.string.isRequired,
    age: (props, propName) => { // custom validator
      if (props[propName] < 0) return new Error('age must be positive')
    }
  })
}

Auto-generate JSON documentation from propTypes + JSDoc comments. Run: react-docgen button.js

Chapter 4: Compose All the Things

🐋 Container & Presentational Pattern
Container (Smart)
• Makes API calls
• Holds state
• Has event handlers
• Written as class
• Named: GeolocationContainer
Presentational (Dumb)
• Only renders UI
• Gets data via props
• Stateless function
• Reusable in Storybook
• Named: Geolocation
render() {
  return <Geolocation {...this.state} /> // spread state as props
}
🚫 Mixins (Avoid!)
Problems with Mixins
• Only work with createClass, not ES6 classes
• Namespace clashing between mixins
• Implicit dependencies — unclear what a mixin requires
• Pollutes component state
• Mixins depending on other mixins = tight coupling
🔮 Higher-Order Components (HoC)
Definition
const HoC = Component => EnhancedComponent
Takes a component, returns enhanced one. Named with with prefix.
// withClassName HoC
const withClassName = Component => props => (
  <Component {...props} className="my-class" />
)

// Usage
const EnhancedButton = withClassName(Button)
Key HoC Rules
• Always spread {...this.props} to stay transparent
• Use with* naming convention (withInnerWidth, withData)
• Use partial application for parameterized HoCs
• Compose with compose(hoc1, hoc2)(Component)
• Don't overuse — adds render/lifecycle overhead
🎯 recompose Library
  • flattenProp('user') — spread object prop into individual props
  • renameProp('username', 'name') — rename a prop
  • getContext({ currency: PropTypes.string }) — extract from context
  • compose(hoc1, hoc2, hoc3)(Component) — chain HoCs cleanly
👶 Function as Child Pattern
// Component receives a function as children
const FunctionAsChild = ({ children }) => children()

// Usage
<FunctionAsChild>
  {() => <div>Hello!</div>}
</FunctionAsChild>

// With parameters
<Fetch url="...">
  {data => <List data={data} />}
</Fetch>
Benefits
• Variables at runtime (not fixed props)
• Consumer chooses variable names
• Highly reusable wrapper
• Used by react-motion

Chapter 5: Proper Data Fetching

🔄 Unidirectional Data Flow
Core Rules
• Data flows top → bottom only, via props
• Props are read-only — never modify them
• Children notify parents via callbacks
• Siblings share via common parent state
📞 Communication Patterns
Child → Parent (Callbacks)
const Buttons = ({ onDecrement, onIncrement }) => (
  <div>
    <button onClick={onDecrement}>-</button>
    <button onClick={onIncrement}>+</button>
  </div>
)
Sibling → Sibling (Common Parent)
// Parent holds state, passes to both siblings
<Display counter={this.state.counter} />
<Buttons onIncrement={this.handleIncrement} />
🌐 Data Fetching Best Practices
  • Use componentDidMount for data fetching (runs client-side only)
  • Not componentWillMount — runs on server too, async issues
  • Initialize state with empty data: this.state = { gists: [] }
  • Show spinner during loading (conditional rendering)
componentDidMount() {
  fetch('https://api.github.com/users/gaearon/gists')
    .then(response => response.json())
    .then(gists => this.setState({ gists }))
}
♻️ withData HoC Pattern
const withData = url => Component => (
  class extends React.Component {
    constructor(props) {
      super(props)
      this.state = { data: [] }
    }
    componentDidMount() {
      const endpoint = typeof url === 'function'
        ? url(this.props) // dynamic URL from props
        : url
      fetch(endpoint)
        .then(r => r.json())
        .then(data => this.setState({ data }))
    }
    render() {
      return <Component {...this.props} {...this.state} />
    }
  }
)

// Usage
const withGists = withData(
  props => `https://api.github.com/users/${props.username}/gists`
)
const ListWithGists = withGists(List)
🔃 react-refetch
  • Library by Heroku — simplifies data fetching with HoCs
  • Returns PromiseState object (pending, fulfilled, rejected)
  • Lazy loading: use function value → injected as callable
const connectWithGists = connect(({ username }) => ({
  gists: `https://api.github.com/users/${username}/gists`
}))

const List = ({ gists }) => (
  gists.fulfilled && (
    <ul>{gists.value.map(g => <li key={g.id}>{g.description}</li>)}</ul>
  )
)

Chapter 6: Write Code for the Browser

📋 Forms: Controlled vs Uncontrolled
Uncontrolled
DOM manages state internally. Access with ref or defaultValue. Less React-like.
Controlled ✅
React controls value via state. onChange → setState → re-render with new value.
// Controlled Component
<input
  type="text"
  name="firstName"
  value={this.state.firstName}
  onChange={this.handleChange}
/>

// Single handler for all fields using name attribute
handleChange({ target }) {
  this.setState({ [target.name]: target.value })
}
⚡ Events
Synthetic Events
• React wraps native events in SyntheticEvent
• Consistent API across all browsers
• Pooled — become null after event handler (use e.persist() to keep)
• Single global handler via event delegation (performance optimization)
• Naming: onClick, onChange, onDoubleClick 
// Generic event handler pattern
handleEvent(event) {
  switch (event.type) {
    case 'click': console.log('clicked'); break
    case 'dblclick': console.log('double clicked'); break
  }
}
🔗 Refs
Use Refs Sparingly!
Breaks declarative nature. Use for: DOM focus, integrating imperative libraries, measuring layout.
// Access DOM node
<input ref={element => (this.element = element)} />
handleClick() { this.element.focus() }

// Access component instance (avoid)
<Input ref={element => (this.element = element)} />
handleClick() { this.element.reset() } // calls instance method
🎬 Animations
CSSTransitionGroup
React add-on. Applies CSS classes (*-appear, *-enter, *-leave). Simple transitions.
react-motion
Physics-based animations. Uses Function as Child pattern. Spring interpolation.
// react-motion
<Motion defaultStyle={{ opacity: 0 }} style={{ opacity: spring(1) }}>
  {style => <h1 style={style}>Hello</h1>}
</Motion>
🔷 SVG in React
const Circle = ({ x, y, radius, fill }) => (
  <svg>
    <circle cx={x} cy={y} r={radius} fill={fill} />
  </svg>
)
Circle.defaultProps = { fill: 'red' }

// Composable: RedCircle, SmallCircle, etc.

Chapter 7: Make Your Components Look Beautiful

💅 7 Problems with CSS at Scale
  • 1. Global namespace — all selectors pollute global scope
  • 2. Dependencies — hard to know what CSS a component needs
  • 3. Dead code — can't safely delete unused CSS
  • 4. Minification — can't safely minify class names
  • 5. Sharing constants — CSS and JS can't share values
  • 6. Non-deterministic resolution — load order affects styles
  • 7. Isolation — styles from one component leak into others
💻 Solution 1: Inline Styles
const style = {
  backgroundColor: 'red', // camelCase, no hyphens
  width: 320,            // numbers = pixels
  WebkitTransition: 'all', // vendor prefix: capitalize
  msTransition: 'all'  // ms is lowercase exception
}
Inline Style Limitations
❌ No pseudo-selectors (:hover)
❌ No media queries
❌ No style fallbacks
❌ No CSS animations
❌ Hard to debug
❌ Larger server-rendered HTML
⚡ Solution 2: Radium
  • HoC that wraps component: export default radium(Button)
  • Adds JS-based :hover, :active, :focus
  • Supports media queries (requires <StyleRoot> wrapper)
  • Injects !important media query styles into <style> tag
const styles = {
  color: 'red',
  ':hover': { color: 'white' },
  '@media (max-width: 480px)': { width: 160 }
}
🎭 Solution 3: CSS Modules
How It Works
1. Import CSS: import styles from './button.css'
2. Use: <button className={styles.button}>
3. Webpack transforms class names to unique hashes
4. Locally scoped — no global pollution!
Key Features
• :global .button — opt-out of scoping
• composes: background-red — inherit rules from another class
• Supports all CSS (pseudo-classes, media queries, animations)
• Debug: localIdentName=[local]--[hash:base64:5]
Atomic CSS Modules
Single-rule utility classes + CSS Modules composes = fast prototyping + locally scoped.
💎 Solution 4: Styled Components
const Button = styled.button`
  background-color: #ff0000;
  width: 320px;
  &:hover { color: white; }
  @media (max-width: 480px) { width: 160px; }
`
  • Uses ES2015 Tagged Template Literals
  • Generates unique class names, injects into <head>
  • Supports all CSS including pseudo-classes + media queries
  • Props in templates: dynamic styling
  • Theming via ThemeProvider

Chapter 8: Server-Side Rendering (SSR)

🌍 Universal Applications
What Is It?
Same code runs on both server AND client. Also called "isomorphic" though "Universal" is preferred.
3 Reasons to Use SSR
1. SEO — crawlers get real HTML, not empty shell
2. Common code base — share logic, models, components
3. Better perceived performance — users see content immediately
Don't Underestimate Complexity
Server routes, data fetching, caching. Only add SSR when truly needed (SEO, social sharing, performance budget).
⚙️ SSR Key API
// Server (Express)
import ReactDOM from 'react-dom/server'

app.get('/', (req, res) => {
  const body = ReactDOM.renderToString(<App />)
  res.send(`<html><body>
    <div id="app">${body}</div>
    <script src="/bundle.js"></script>
  </body></html>`)
})

// Client still renders normally — hydrates the SSR output
ReactDOM.render(<App />, document.getElementById('app'))
renderToString Output
Returns HTML string with React data attributes: data-reactroot, data-reactid, data-reactchecksum — used for client hydration.
📦 Data Fetching with SSR
  • componentDidMount doesn't run on server
  • componentWillMount runs on server but renderToString is sync
  • Solution: fetch data BEFORE rendering, pass as props
  • Use isomorphic-fetch for fetch on both client and server
app.get('/', (req, res) => {
  fetch('https://api.github.com/...')
    .then(r => r.json())
    .then(gists => {
      const body = ReactDOM.renderToString(<App gists={gists} />)
      res.send(template(body))
    })
})
Next.js
Framework by Zeit that handles SSR, routing, and code splitting automatically. Zero config.

Chapter 9: Performance Optimization

⚡ Reconciliation & Keys
How Reconciliation Works
React diffs virtual DOM trees. If type changed → destroy + create new. If type same → update props.
Keys in Lists
Help React identify which items changed. Must be: stable, unique among siblings, not array index.
❌ Never use index as key
items.map((item, i) => <li key={i}>{item}</li>) // ❌ BAD
items.map(item => <li key={item.id}>{item.name}</li>) // ✅ GOOD
🚀 Optimization Techniques
shouldComponentUpdate
shouldComponentUpdate(nextProps, nextState) {
  return nextProps.value !== this.props.value
  // Return false to skip re-render
}
When to Re-render Rules
• Stateless functional components: no shouldComponentUpdate — always re-render
• Pure components (React.PureComponent): shallow comparison automatically
• Avoid creating functions in render — new reference every time
Constant Props Optimization
// ❌ New function reference on every render
<Button onClick={() => this.handleClick()} />

// ✅ Stable reference
<Button onClick={this.handleClick} />
🔧 Performance Tools
  • why-did-you-update: logs unnecessary re-renders to console
  • React DevTools: profiler, component tree inspection
  • Immutable.js: enforces immutability, enables fast equality checks
  • Babel plugins: compile-time optimizations (inline constants, etc.)

Chapter 10: Testing & Debugging

🧪 Testing Tools
Jest
Facebook's test runner. Zero config. Built-in mocking. Snapshot testing. Fast parallel execution.
Enzyme (Airbnb)
React-specific testing utilities. shallow(), mount(), render() methods.
Shallow vs Mount
• shallow(): renders only one level deep. Fast. No DOM. Good for unit tests.
• mount(): full DOM rendering. Tests integration with DOM. Slower.
📸 Snapshot Testing
it('renders correctly', () => {
  const tree = renderer
    .create(<Button text="Click me!" />)
    .toJSON()
  expect(tree).toMatchSnapshot()
})
  • First run: creates snapshot file
  • Subsequent runs: compares to saved snapshot
  • Update with jest --updateSnapshot (-u)
  • Great for catching unintended UI changes
🔍 Testing HoCs & Page Object Pattern
Testing HoCs
Export both enhanced AND original component. Test original without HoC wrapping for simpler unit tests.
Page Object Pattern
Abstraction layer over UI elements. Encapsulates selectors. Tests describe behavior, not implementation. Makes tests maintainable.
🐛 Debugging
  • React DevTools browser extension: inspect component tree, state, props
  • Error boundaries: catch errors in component subtrees (React 16)
  • Use console.log(this.state) in render for quick debugging
  • Why-did-you-update package for performance debugging
  • react-lumberjack: time-travel debugging (experimental)

Chapter 11: Anti-Patterns to AVOID

🚨 Anti-Pattern 1: Initializing State from Props
❌ The Problem
constructor(props) {
  super(props)
  this.state = {
    price: `${props.currency}${props.value}` // ❌
  }
}
// State never updates when props change!
// Constructor only runs once.
✅ The Fix
getPrice() {
  return `${this.props.currency}${this.props.value}`
}
render() { return <div>{this.getPrice()}</div> }
Exception
OK to init from props only if prop is explicitly named "initial" or "default" and you never expect it to update.
🚨 Anti-Pattern 2: Mutating State
❌ Never Mutate State Directly
this.state.items.push(newItem) // ❌ Direct mutation
this.state.count++ // ❌ Direct mutation
✅ Always Use setState
this.setState({
  items: [...this.state.items, newItem], // ✅ New array
  count: this.state.count + 1 // ✅
})
🚨 Anti-Pattern 3: Using Index as Key
❌ Index as Key
items.map((item, i) => <Item key={i} />)
// When list is reordered → wrong components update
// State gets mixed between items
✅ Stable Unique Key
items.map(item => <Item key={item.id} />)
// Use ID from data, or generate stable UUID
🚨 Anti-Pattern 4: Spreading Props on DOM Elements
❌ Spreading Unknown Props onto DOM Elements
const MyComponent = (props) => <div {...props} />
// Passes unknown/custom props to div
// React warns: Unknown props: 'isLoggedIn', etc.
✅ Destructure and only pass known HTML attributes
const MyComponent = ({ className, children, ...rest }) => (
  <div className={className}>{children}</div>
  // rest is consumed, not passed to DOM
)

🃏 Flashcards (tap to flip)

CONCEPT
What is a Higher-Order Component?
Tap to reveal answer
ANSWER
A function that takes a component and returns a new enhanced component. Pattern: const Enhanced = withX(Component). Used to share behavior without mixins.
CONCEPT
What's the difference between controlled and uncontrolled components?
ANSWER
Controlled: React owns value via state + onChange. Uncontrolled: DOM manages its own state internally. Controlled is preferred in React.
CONCEPT
Why should you NOT use array index as a key?
ANSWER
When list reorders/items are added/removed, index changes → React maps wrong state to wrong components. Use stable IDs from data.
CONCEPT
Where should data fetching happen and why?
ANSWER
componentDidMount — it only runs on the client, not during server-side rendering. componentWillMount runs on server too and renderToString is synchronous.
CONCEPT
What is reconciliation in React?
ANSWER
The diffing process that compares old and new virtual DOM trees. If element type changes → rebuild subtree. If type same → update props. Keys help identify list items.
CONCEPT
What is the Container/Presentational pattern?
ANSWER
Container: logic, API calls, state, handlers (class component). Presentational: pure UI from props (stateless function). Separates concerns for better reusability.
CONCEPT
What does renderToString do and what is it used for?
ANSWER
Returns HTML string of component's rendered output. Used in Server-Side Rendering. Includes React data attributes (data-reactroot) for client hydration.
CONCEPT
What's wrong with initializing state from props?
ANSWER
Constructor runs only once. If props change later, state won't update. Fix: compute derived values in render method instead.
CONCEPT
What is the Function as Child pattern?
ANSWER
children prop is a function instead of JSX. Component calls children(params) passing values at runtime. Used by react-motion. Flexible — consumer chooses variable names.
CONCEPT
What are 3 main benefits of CSS Modules?
ANSWER
1. Locally scoped class names (no global pollution) 2. Explicit dependencies (import CSS per component) 3. Dead code elimination (know which CSS each component uses)
CONCEPT
How does event delegation work in React?
ANSWER
React attaches a single event handler to the root element. When events bubble up, React dispatches to the right component. More memory efficient than per-element handlers.
CONCEPT
When should you use shouldComponentUpdate?
ANSWER
When a component re-renders too often with same props/state. Return false to skip re-render. PureComponent does shallow comparison automatically. Don't use prematurely.

1. JSX expression <Button /> compiles to what JavaScript?

Capital B = Component reference. Lowercase <button> → string 'button'. Capital <Button> → the Button variable itself.

2. Which lifecycle method is best for data fetching in React?

componentDidMount runs only on client after first render. componentWillMount runs on server too, causing issues with async SSR.

3. What is the main problem with using array index as a key?

Index changes when items are added/removed/reordered. React uses the key to match components across renders, so wrong keys cause wrong state assignments.

4. What distinguishes a Container component from a Presentational component?

Container = logic, state, API calls. Presentational = pure UI from props, usually stateless function. Separation makes both more reusable and testable.

5. What does a Higher-Order Component (HoC) return?

HoC = Component => EnhancedComponent. It's a function that takes a component and returns a new one with added behavior.

6. What is renderToString used for?

ReactDOM.renderToString() is the core SSR API. Returns an HTML string with data-reactroot attributes for client hydration.

7. Which CSS-in-JS approach requires wrapping the app in <StyleRoot>?

Radium requires StyleRoot for media queries to work correctly, especially with SSR. It injects !important media query styles into a style element.

8. Why should you bind event handlers in the constructor instead of in render?

New arrow function in render = new reference each render = child component sees a "new" prop every time = unnecessary re-renders. Constructor binding is stable.

9. What happens when you call setState inside an event handler?

React batches setState calls in event handlers for performance. Logging this.state immediately after setState shows the old value. Use callback: setState({}, () => console.log(this.state))

10. What is the Function as Child pattern?

FaC: children is a function called by the component with runtime values. Example: <Fetch url="...">{data => <List data={data} />}</Fetch>

11. Which is an anti-pattern when using props?

Spreading unknown props on DOM elements passes non-HTML attributes to the DOM, causing React warnings. Destructure and only pass known HTML attributes.

12. What does CSS Modules' "composes" feature do?

Unlike SASS @extend, composes applies multiple scoped class names to the element in the DOM without duplicating CSS rules. Efficient and maintainable.

13. In unidirectional data flow, how does a child communicate with its parent?

Data flows down via props. Communication goes up via callbacks. Parent passes onSomething function, child calls it when needed. Parent owns the state.

14. What is a Synthetic Event in React?

SyntheticEvent wraps the native event, normalizing differences between browsers. It's pooled (reused) for performance — becomes null after handler unless you call e.persist().

15. What does propTypes.isRequired do?

PropTypes validation only runs in development mode (disabled in production for performance). Shows warning but doesn't throw or prevent rendering.
